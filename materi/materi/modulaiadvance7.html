Building an Application with Google AI Studio

Pada pertemuan ini kita mulai berpindah dari belajar konsep AI Engineering menuju membangun aplikasi AI secara nyata. Google AI Studio saat ini memiliki Build mode yang memungkinkan kita mendeskripsikan aplikasi menggunakan bahasa alami, kemudian AI menghasilkan struktur dan kode aplikasi. Untuk aplikasi web, AI Studio kini menyediakan lingkungan full-stack dengan frontend dan runtime server-side berbasis Node.js.

Tujuan Pembelajaran

Setelah menyelesaikan pertemuan ini, peserta diharapkan mampu:

  1. Memahami fungsi Google AI Studio.
  2. Memahami konsep Build mode.
  3. Memahami hubungan prompt dengan pembuatan aplikasi.
  4. Membuat spesifikasi aplikasi menggunakan bahasa alami.
  5. Membuat aplikasi sederhana menggunakan Google AI Studio.
  6. Memahami struktur dasar aplikasi yang dihasilkan AI.
  7. Menguji aplikasi secara mandiri.
  8. Memperbaiki aplikasi menggunakan instruksi kepada AI (iterative prompt).
  9. Memahami dasar keamanan API key.
  10. Memahami bahwa AI coding bukan berarti programmer tidak perlu memahami kode.

Secara sederhana, Google AI Studio adalah lingkungan untuk bereksperimen dan membangun aplikasi menggunakan model Gemini.

Sekarang AI dapat membantu sebagian besar proses tersebut. Dengan Google AI Studio Build mode, kita dapat memberikan instruksi menggunakan bahasa manusia sehari-hari seperti: 

Buat aplikasi chatbot kamus Bahasa Inggris.
Pengguna dapat memasukkan kata.

AI kemudian membuat aplikasi berdasarkan instruksi tersebut. Google menjelaskan bahwa Build mode dapat membuat aplikasi web full-stack dan juga aplikasi Android native. Untuk pembelajaran AI Engineering kita akan fokus terlebih dahulu pada aplikasi web karena lebih sederhana untuk dipahami dan diuji langsung melalui browser.

Analogi untuk Peserta Tunanetra

Bayangkan Anda mendatangi seorang arsitek digital terampil. Anda tidak perlu menyusun batu bata atau mengecor lantai sendiri; Anda cukup mendeskripsikan: "Tolong buatkan ruangan belajar dengan satu pintu masuk lebar yang mudah dilalui, meja komputer di tengah, dan ventilasi udara yang sejuk." Arsitek tersebut akan membuat denah dan mendirikan ruangannya untuk Anda. Demikian halnya Build mode: kata-kata dan deskripsi logis Anda adalah cetak biru aplikasinya.

Bagian 2 — Mengapa Ini Penting untuk AI Engineer?

Seorang AI Engineer tidak selalu harus menulis seluruh kode aplikasi dari awal baris per baris. Yang jauh lebih penting adalah memahami kerangka masalah dan solusinya: 

Apa masalahnya?
Apa solusi yang dibutuhkan?
Data apa yang digunakan?
Model AI apa yang diperlukan?
Tool apa yang diperlukan?
Bagaimana aplikasi diuji?
Bagaimana keamanan dijaga?

AI dapat membantu menulis kode. Tetapi seorang AI Engineer tetap harus mampu:

  • Membaca kode;
  • Memahami struktur aplikasi;
  • Memberikan instruksi yang tepat;
  • Menguji hasil;
  • Menemukan kesalahan;
  • Memperbaiki aplikasi;
  • Menjaga keamanan data.

Prinsip Utama AI Engineer:
AI membantu programmer membuat aplikasi, bukan menggantikan pemahaman programmer.

Bagian 4 — Apa Itu Prompt untuk Membuat Aplikasi?

Pada pertemuan sebelumnya kita sudah mengenal prompt untuk menghasilkan teks atau jawaban. Namun ketika membuat aplikasi utuh, prompt harus jauh lebih terstruktur dan berorientasi arsitektur.

Jangan hanya mengatakan:

Buat aplikasi kamus.

Instruksi tersebut terlalu umum dan membuat AI menebak-nebak kebutuhan Anda.

Lebih baik susun secara terperinci:

Buat aplikasi web chatbot kamus Bahasa Inggris.

Fitur:
1. Pengguna dapat memasukkan kata Bahasa Inggris.
2. Aplikasi menampilkan arti Bahasa Indonesia.
3. Aplikasi menampilkan contoh kalimat.
4. Aplikasi memiliki riwayat pencarian.
5. Pengguna dapat menghapus riwayat.

Buat antarmuka sederhana dan mudah digunakan
oleh pengguna screen reader.
Gunakan label yang jelas pada setiap input
dan tombol.

Prompt tersebut memberikan konteks dan batasan teknis yang sangat terarah bagi AI.

Bagian 5 — Formula Prompt untuk AI Coding

Peserta dapat menggunakan pola atau kerangka kerja (formula) terstandar berikut saat merancang aplikasi dengan AI:

Buat [jenis aplikasi]

Tujuan:
[tujuan aplikasi]

Pengguna:
[siapa yang menggunakan]

Fitur:
1. ...
2. ...
3. ...

Input:
...

Output:
...

Teknologi:
...

Ketentuan:
...

Contoh Penerapan Formula:

Buat aplikasi web AI Assistant untuk belajar Bahasa Inggris.

Tujuan:
Membantu pengguna mempelajari kosakata Bahasa Inggris.

Pengguna:
Pelajar dan pengguna umum.

Fitur:
1. Input kata Bahasa Inggris.
2. Menampilkan arti Bahasa Indonesia.
3. Menampilkan contoh kalimat.
4. Menyimpan riwayat pencarian.
5. Menyediakan tombol hapus riwayat.

Ketentuan aksesibilitas:
1. Gunakan label pada semua input.
2. Semua tombol dapat digunakan dengan keyboard.
3. Jangan hanya menggunakan warna sebagai penanda informasi.
4. Gunakan struktur heading yang jelas.
5. Pastikan hasil AI dapat dibaca screen reader.

Prompt dengan formula ini mencerminkan cara berpikir seorang AI Engineer profesional yang memikirkan aspek fungsionalitas sekaligus kemudahan akses sejak detik pertama.

Bagian 7 — Prompt Praktik Utama

Di Google AI Studio Build mode, peserta dapat memasukkan prompt utama berikut: 

Buat aplikasi web bernama English Learning Assistant.

Tujuan aplikasi:
Membantu pengguna belajar Bahasa Inggris
menggunakan AI.

Fitur utama:
1. Pengguna dapat memasukkan pertanyaan.
2. AI menjawab pertanyaan tentang Bahasa Inggris.
3. AI dapat menjelaskan arti kata.
4. AI dapat memberikan contoh kalimat.
5. AI dapat memberikan latihan sederhana.
6. Tampilkan percakapan pengguna dan AI.
7. Sediakan tombol untuk menghapus percakapan.

Aksesibilitas:
1. Semua input harus memiliki label yang jelas.
2. Semua tombol dapat digunakan dengan keyboard.
3. Gunakan heading HTML yang terstruktur.
4. Jangan menggunakan informasi yang hanya dapat
   dipahami berdasarkan warna.
5. Pastikan hasil percakapan dapat dibaca dengan
   screen reader.
6. Gunakan teks yang jelas dan sederhana.

Buat desain sederhana dan responsif.

Prompt ini sangat lengkap. Peserta tidak perlu menghafalnya kata per kata, melainkan memahami bagaimana setiap komponen kebutuhan disusun dengan sistematis.

Bagian 8 — Mengapa Kita Harus Memikirkan Aksesibilitas?

Dalam pengembangan aplikasi konvensional, developer sering kali hanya memikirkan estetika visual: "Apakah aplikasi terlihat cantik dan modern?" Namun dalam rekayasa perangkat lunak yang inklusif, pertanyaan wajibnya adalah: "Apakah aplikasi dapat digunakan secara mandiri oleh semua orang?"

Bagi pengguna pembaca layar (screen reader seperti NVDA atau JAWS), hal-hal berikut sangat krusial: 

Input memiliki label eksplisit
        │
        v
Tombol memiliki nama yang jelas (Accessible Name)
        │
        v
Heading terstruktur rapi (H1, H2, H3)
        │
        v
Navigasi keyboard lengkap (Tab, Shift+Tab, Enter)
        │
        v
Pesan error terbaca dan terdengar
        │
        v
Hasil respon AI langsung terdengar jelas

Oleh karena itu, prinsip emas AI Engineer: Aksesibilitas harus dimasukkan sejak prompt pertama, bukan baru ditambal belakangan ketika aplikasi sudah selesai dibuat.

Bagian 9 — Memahami Hasil yang Dibuat AI

Setelah prompt dijalankan, AI Studio akan menghasilkan aplikasi lengkap beserta kode sumber dan jendela preview langsung. Untuk aplikasi web, AI Studio menyusun struktur kode frontend (biasanya React/JSX) dan runtime server-side berbasis Node.js.

Struktur file yang umumnya terlihat antara lain:

src/
    App.jsx      <-- Komponen utama tampilan & logika
    main.jsx     <-- Titik masuk aplikasi web
package.json     <-- Daftar pustaka/dependensi aplikasi

Jangan panik ketika melihat banyak baris kode. Kita tidak perlu menghafal atau membaca seluruh baris sekaligus. Gunakan kerangka berpikir terarah: 

File
 │
 v
Apa fungsinya?
 │
 v
Bagian mana yang penting?
 │
 v
Apa yang terjadi ketika dijalankan?

Bagian 10 — Belajar Membaca Kode Hasil AI

Misalnya di dalam file src/App.jsx kita menemukan potongan kode berikut:

function App() {
    return (
        <main>
            <h1>English Learning Assistant</h1>
        </main>
    );
}

Cukup pahami elemen-elemen utamanya:

  • function App(): fungsi JavaScript/React yang mewakili seluruh komponen tampilan aplikasi.
  • <main>: penanda landmark HTML untuk area konten utama halaman yang sangat disukai screen reader.
  • <h1>: heading tingkat pertama yang dibaca screen reader sebagai judul utama halaman.

Jadi AI-generated code tetap harus kita baca dan verifikasi sedikit demi sedikit.

Bagian 11 — Mengembangkan Aplikasi dengan Percakapan

Salah satu kemampuan yang menarik adalah kita dapat meminta AI melakukan perubahan secara bertahap melalui dialog interaktif.

Contoh instruksi kelanjutan 1:

Tambahkan fitur tombol "Baca Jawaban".
Gunakan text-to-speech browser (SpeechSynthesis API).
Pastikan tombol dapat digunakan
dengan keyboard dan screen reader.

Contoh instruksi kelanjutan 2:

Tambahkan fitur mode latihan.
Pengguna memasukkan jawaban,
kemudian AI memberikan evaluasi ramah.

Contoh instruksi kelanjutan 3:

Tambahkan riwayat pertanyaan.
Sediakan tombol untuk menghapus semua riwayat.

Dengan cara tersebut aplikasi dikembangkan dan diperkaya secara bertahap.

Bagian 13 — Mengenal API Key

Aplikasi AI biasanya membutuhkan akses ke model AI melalui API (Application Programming Interface). Secara sederhana:

    │
    v
API
    │
    v

    v

API key digunakan untuk mengautentikasi dan mengamankan penggunaan API. Google saat ini merekomendasikan penggunaan Gemini Interactions API untuk proyek baru; API tersebut mendukung percakapan, alat (tools), function calling, dan workflow agentic (AI Agent). Namun peserta tidak perlu menghafal seluruh kode API terlebih dahulu, melainkan memahami prinsip alurnya: 

Aplikasi ──> meminta layanan AI ──> API ──> model AI ──> hasil

Bagian 14 — Keamanan API Key

Ini merupakan konsep yang sangat penting bagi AI Engineer. Jangan menulis API key secara langsung di kode frontend seperti: 

// CARA INI SANGAT BERBAHAYA - JANGAN DITIRU!
const apiKey = "KUNCI_RAHASIA_ANDA";

Cara seperti ini berbahaya karena siapa pun dapat melihat kunci rahasia Anda melalui fitur View Source / Inspect Element peramban. API key seharusnya disimpan sebagai secret di sisi server.

Google AI Studio Build mode saat ini dapat mengatur GEMINI_API_KEY sebagai secret pada lingkungan server-side aplikasi sehingga key tidak perlu diekspos di kode frontend.

Prinsip sederhananya:

ALUR AMAN:
API Key ──> Secret ──> Server ──> Gemini API

ALUR SALAH:
API Key ──> Kode Frontend ──> Semua pengguna dapat melihat

Bagian 15 — Panduan Pengguna Screen Reader di Google AI Studio

Bagi peserta tunanetra yang menggunakan pembaca layar (NVDA atau JAWS), berikut adalah langkah-langkah navigasi ramah keyboard dari membuka situs hingga mengeksekusi Build mode:

Langkah 1: Membuka Google AI Studio di Browser

Gunakan Google Chrome, Microsoft Edge, atau Mozilla Firefox:

  • Tekan shortcut Windows + R pada keyboard.
  • Ketik chrome atau msedge, lalu tekan Enter.
  • Tekan shortcut Ctrl + L atau Alt + D untuk fokus ke Address Bar.
  • Ketik alamat URL resmi: aistudio.google.com lalu tekan Enter.
  • Pastikan Anda telah masuk (login) dengan akun Google Anda.

Langkah 2: Mengenal Antarmuka & Memilih Build Mode

  • Gunakan tombol shortcut H pada NVDA/JAWS untuk melompat antar heading halaman.
  • Gunakan tombol Tab atau panah bawah untuk menelusuri menu navigasi dan temukan tombol/tab "Build" atau "New Prompt".
  • Tekan Enter atau Spasi untuk memilih Build mode. Screen reader akan membacakan konfirmasi antarmuka pembuatan aplikasi telah terbuka.

Langkah 3: Menavigasi ke Kotak Input Prompt

  • Tekan shortcut E (fitur cepat NVDA/JAWS untuk langsung melompat ke kotak edit/input teks).
  • Screen reader akan membacakan: "Prompt edit multi-line" atau "Describe the app you want to build".
  • Tekan Enter untuk mengaktifkan Focus Mode (terdengar bunyi klik penanda siap mengetik).

Langkah 4: Memasukkan Prompt Spesifikasi Aplikasi

Salin teks prompt dari Bagian 7 di modul ini. Tekan Ctrl + V di dalam kotak prompt untuk menempelkan spesifikasi aplikasi English Learning Assistant.

Langkah 5: Mengeksekusi Pembuatan Aplikasi (Run / Build)

  • Tekan tombol Escape satu kali untuk keluar dari mode edit teks (kembali ke Browse Mode).
  • Tekan Tab hingga screen reader membacakan tombol "Run" atau "Build" (atau gunakan shortcut Ctrl + Enter langsung saat di kotak teks).
  • Tekan Enter untuk menjalankan. Tunggu beberapa saat selagi AI Studio menyusun file aplikasi dan menyiapkan server lokal.

Langkah 6: Menjelajahi Preview Aplikasi dengan Screen Reader

  • Gunakan tombol H untuk mencari heading Preview atau tombol landmark untuk menuju area bingkai aplikasi yang dihasilkan.
  • Tekan tombol Tab untuk mencoba seluruh tombol dan kotak isian:
    • Dengarkan apakah kotak input dibacakan labelnya dengan jelas.
    • Pastikan tombol memiliki nama yang deskriptif saat disentuh fokus keyboard.
    • Ketikkan pertanyaan uji coba dan dengarkan bagaimana jawaban Gemini disajikan.

Bagian 16 — Latihan Praktik

Latihan Praktik 1: Membuat & Menguji Aplikasi Pertama

Buat aplikasi English Learning Assistant dengan komponen minimal yang harus dimiliki:

  1. Judul aplikasi yang jelas.
  2. Kotak pertanyaan dengan label.
  3. Tombol kirim yang responsif.
  4. Jawaban AI yang terbaca runtut.
  5. Riwayat percakapan pengguna dan AI.
  6. Tombol hapus percakapan.
  7. Struktur HTML yang ramah pengguna screen reader.

Setelah aplikasi berhasil dibuat di jendela preview, lakukan pengujian dengan pertanyaan nyata berikut:

  • Uji 1: Apa arti kata beautiful?
  • Uji 2: Buatkan contoh kalimat menggunakan beautiful.
  • Uji 3: Apa perbedaan house dan home?

Latihan Praktik 2: Memperbaiki Aplikasi dengan AI (Iterasi Aksesibilitas)

Setelah aplikasi berjalan, jangan langsung berhenti. Kirimkan instruksi perbaikan melalui kotak dialog AI Studio: 

Periksa aplikasi ini untuk masalah aksesibilitas
bagi pengguna screen reader.

Perbaiki:
1. Label input.
2. Nama tombol.
3. Struktur heading.
4. Navigasi keyboard.
5. Pembacaan hasil AI.
6. Pesan error.

Kemudian lakukan pengujian ulang. Ini merupakan latihan penting karena AI Engineer tidak hanya membuat aplikasi, tetapi juga melakukan testing dan continuous improvement.
