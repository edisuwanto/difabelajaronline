Building AI Agent with Google ADK

Pada pertemuan ini kita akan mempelajari secara mendalam framework resmi dari Google untuk membangun agen cerdas, yaitu Google ADK (Agent Development Kit). Modul ini diawali dengan teori fundamental tentang filosofi, arsitektur, 4 pilar utama, dan siklus kerja Google ADK sebelum melangkah ke persiapan teknis dan praktik. Selanjutnya, kita akan mengimplementasikan pengetahuan tersebut dengan membuat proyek nyata: Social Media Management Assistant yang mampu memantau konten, memperbarui status progres, menghitung engagement rate, serta memberikan rekomendasi kerja berbasis data tanpa halusinasi. Seluruh instruksi disusun bertahap dan ramah bagi pengguna screen reader seperti NVDA atau JAWS.

Tujuan Pembelajaran

Setelah menyelesaikan pertemuan ini, peserta diharapkan mampu:

  1. Memahami konsep dasar, filosofi, dan 4 pilar arsitektur Google ADK (Agent Development Kit).
  2. Membedakan karakteristik Model Bahasa (LLM), Chatbot Konvensional, dan Autonomous AI Agent.
  3. Memahami siklus penalaran dan eksekusi AI Agent (Reasoning, Action, Observation, Response).
  4. Memahami bagaimana Google ADK memetakan fungsi Python biasa menjadi Function Tools yang dipahami AI secara otomatis.
  5. Menyiapkan lingkungan pengembangan terisolasi dengan Python Virtual Environment (.venv).
  6. Menginstal paket resmi google-adk dan mengelola Gemini API Key secara aman melalui file .env.
  7. Membuat AI Agent menggunakan kelas Agent pada Google ADK.
  8. Membuat Function Tools untuk mencatat, memantau, dan memperbarui status alur kerja konten media sosial.
  9. Mengimplementasikan analisis data kuantitatif (engagement rate) menggunakan fungsi Python.
  10. Menguji AI Agent melalui antarmuka terminal dan memverifikasi integritas rekomendasi berbasis data faktual.
  11. Memahami arah pengembangan prototipe menjadi aplikasi tim skala profesional.

Bagian Kesatu — Apa Itu Google ADK? (Technical Overview & Filosofi)

Google ADK (Agent Development Kit) adalah framework pengembangan AI Agent tingkat lanjut yang dirancang dan dirilis oleh Google. Framework ini diciptakan untuk membantu para pengembang (developer dan AI engineer) membangun sistem agen kecerdasan buatan yang tidak hanya pandai mengolah kata-kata, tetapi juga mampu memahami instruksi kompleks, mengambil keputusan logis secara bertahap, dan mengeksekusi fungsi perangkat lunak nyata (disebut tools) untuk menyelesaikan sasaran kerja (goal-oriented tasks).

Dalam dunia rekayasa kecerdasan buatan, kita mengenal evolusi interaksi komputer sebagai berikut: 

Generasi 1: Chatbot Biasa
Menerima teks pertanyaan -> Menghasilkan teks jawaban berdasarkan data statis.
Bersifat pasif dan terisolasi dari sistem komputer.
       │
       v
Generasi 2: AI Assistant
Mampu memahami instruksi pengguna lebih luwes, namun masih terbatas pada pemberian saran teks
tanpa kemampuan mengubah status data secara otomatis.
       │
       v
Generasi 3: Autonomous AI Agent (Google ADK)
Menerima tujuan (goal) -> Melakukan penalaran (reasoning) -> Memilih tools komputer (tools execution)
-> Memperbarui data nyata -> Memberikan laporan hasil yang terverifikasi.

Perhatikan tabel perbandingan karakteristik ketiga tingkatan tersebut serta posisi Google ADK:

Kategori Perilaku & Karakteristik Analogi Sederhana
Chatbot Biasa Hanya mencocokkan kata kunci atau merespons kalimat berdasarkan data teks latihan. Tidak memiliki akses ke sistem luar atau eksekusi fungsi. Buku panduan wisata yang hanya menjawab pertanyaan rute tanpa bisa mengemudikan mobil untuk Anda.
AI Agent Memahami tujuan akhir, memecah tugas menjadi langkah-langkah terencana, memanggil fungsi komputer (tools), mengevaluasi hasilnya, dan menyesuaikan langkah berikutnya. Pemandu wisata pribadi yang tidak hanya tahu peta rute, tetapi juga memesankan tiket, memeriksa prakiraan cuaca, dan mengantar Anda ke tujuan.
Google ADK Framework perangkat lunak resmi dari Google yang menyediakan arsitektur terpadu: integrasi model Gemini, otomasi function calling, manajemen memori sesi, serta CLI dan Web Inspector. Sistem operasi atau toolkit standar industri yang memungkinkan teknisi membangun pemandu wisata pribadi tersebut dengan cepat, aman, dan modular.

Analogi untuk Peserta Pengguna Screen Reader

Bayangkan Anda mempekerjakan seorang asisten administrasi di kantor Anda. Jika Anda hanya memberinya buku ensiklopedia, dia hanya bisa menjawab apa yang tercatat di buku itu (itulah Chatbot teks biasa). Namun jika Anda memberinya meja kerja yang dilengkapi buku agenda, kalkulator, lemari arsip, dan stempel persetujuan (perangkat fungsi/tools), maka dia dapat membuka lemari arsip saat Anda bertanya tentang dokumen lama, menghitung pengeluaran dengan kalkulator, dan mencap surat persetujuan (itulah AI Agent). Google ADK adalah peraturan standar operasional (SOP) resmi yang dibuat Google agar asisten Anda tahu kapan harus menggunakan kalkulator dan kapan harus memeriksa lemari arsip secara teratur.

Bagian Kedua — Arsitektur & 4 Pilar Utama Google ADK

Untuk memahami bagaimana Google ADK bekerja di balik layar, kita perlu mengenal 4 pilar arsitektur utamanya: 

                    ┌────────────────────────────────────────┐
                    │            PENGGUNA / USER             │
                    └───────────────────┬────────────────────┘
                                        │ Instruksi Alami
                                        v
┌────────────────────────────────────────────────────────────────────────────────────┐
│                             GOOGLE ADK (AGENT CORE)                                │
│                                                                                    │
│   1. BRAIN / MODEL (Gemini)          ◄───►   2. ORCHESTRATION & INSTRUCTION        │
│   Penalaran logis & pemahaman bahasa        Aturan kerja, persona, batasan etika   │
│                                                                                    │
│   3. CONTEXT & SESSION MEMORY        ◄───►   4. FUNCTION TOOLS (Kode Python)       │
│   Penyimpan status & konteks obrolan        Kalkulator, database, akses API nyata  │
└───────────────────────────────────────┬────────────────────────────────────────────┘
                                        │
                                        v
                       TINDAKAN NYATA & HASIL TERVERIFIKASI

Mari kita bedah fungsi masing-masing pilar tersebut:

  1. Brain / Model AI (Keluarga Gemini): Bertindak sebagai pusat pemikiran (otak). Model ini bertugas mencerna kalimat manusia yang bebas, menentukan niat pengguna (intent), dan menyusun strategi penyelesaian masalah.
  2. Function Tools (Tangan dan Kaki Agen): Fungsi-fungsi bahasa pemrograman Python biasa yang Anda tulis. Tools ini bertugas menghubungkan AI dengan dunia nyata, misalnya membaca data di memori, menulis ke database, menghitung angka pasti, atau mengirim pesan ke server.
  3. Context & Session Memory (Ingatan Percakapan): Mekanisme yang menjaga riwayat interaksi dan status data antar giliran percakapan (multi-turn dialog), sehingga agen tidak mengalami "amnesia" di tengah proses kerja.
  4. Orchestration & System Instruction (SOP & Kebijakan): Arahan sistem yang memandu karakter, etika, dan batasan operasional agen. Melalui instruksi ini, kita menegaskan agar agen tidak berhalusinasi, selalu ramah pengguna disabilitas, dan hanya bertindak sesuai kewenangan.

Siklus Kerja ReAct (Reasoning - Action - Observation - Response)

Saat pengguna mengirimkan permintaan, Google ADK menjalankan siklus yang dinamakan ReAct:

1. REASON (Menalar):
   Model AI membaca instruksi dan menalar: "Pengguna ingin melihat daftar konten media sosial.
   Saya memiliki tool bernama 'lihat_konten'. Saya harus memanggil tool tersebut."
        │
        v
2. ACTION (Bertindak):
   Google ADK mengeksekusi fungsi Python 'lihat_konten()' di komputer Anda.
        │
        v
3. OBSERVATION (Mengamati):
   Fungsi Python mengembalikan data daftar konten. Model AI membaca output data tersebut.
        │
        v
4. RESPONSE (Menjawab):
   Model AI merangkum data faktual menjadi bahasa manusia yang ramah dibaca oleh screen reader.

Bagian Ketiga — Bagaimana Google ADK Menghubungkan Gemini dengan Kode Python?

Salah satu keunggulan terbesar Google ADK dibanding pendekatan konvensional adalah kemudahannya dalam mendaftarkan fungsi Python menjadi tools AI.

Di masa lalu, pengembang harus menyusun deskripsi fungsi dalam format JSON Schema yang sangat panjang dan rumit agar AI mengerti parameter apa yang dibutuhkan. Namun di Google ADK, Anda cukup menulis fungsi Python standar dengan dua aturan:

  1. Type Hints (Penanda Tipe Data): Menuliskan tipe input dan output (seperti str untuk teks, int untuk bilangan bulat, list untuk daftar).
  2. Docstrings (Komentar Dokumentasi Fungsi): Menuliskan penjelasan singkat di dalam tanda petik tiga ("""...""") mengenai apa tugas fungsi tersebut.

Perhatikan contoh elegan berikut:

def update_status(konten_id: int, status_baru: str) -> str:
    """Memperbarui status pekerjaan konten media sosial berdasarkan ID konten."""
    # Kode Python Anda di sini...

Saat fungsi di atas dimasukkan ke dalam daftar tools=[update_status] pada agen ADK, Google ADK secara otomatis menerjemahkan docstring dan type hints tersebut menjadi format pemanggilan yang dimengerti oleh model Gemini. Model langsung paham bahwa untuk memperbarui status, ia harus meminta parameter konten_id berupa angka dan status_baru berupa teks.

Bagian Keempat — Mengapa Google ADK Sangat Penting untuk AI Engineer?

Sebagai seorang AI Engineer, memahami framework seperti Google ADK memberikan keunggulan kompetitif yang besar:

  • Standar Industri Resmi: Dibangun langsung oleh tim Google DeepMind dan Google Cloud, menjamin kompatibilitas jangka panjang dengan model-model masa depan Gemini.
  • Aksesibilitas Dual-Interface: Menyediakan antarmuka terminal (CLI) berbasis teks murni yang sangat cepat dan ramah screen reader (NVDA/JAWS), serta antarmuka visual berbasis web (ADK Web) untuk inspeksi grafik interaktif.
  • Pencegahan Halusinasi yang Ketat: Karena AI diwajibkan mengambil data melalui tools Python terverifikasi, risiko AI mengarang data angka atau status palsu dapat ditekan seminimal mungkin.
  • Skalabilitas Menuju Produksi: Kode agent yang kita tulis di komputer lokal dapat langsung dipindahkan ke layanan server cloud (seperti Google Cloud Run atau Vertex AI) tanpa merombak logika program dari awal.

Prinsip Utama AI Agent Engineering:
AI menyediakan kemampuan bahasa dan fleksibilitas penalaran, sedangkan kode Python menyediakan kepastian matematika dan integritas penyimpanan data.

Bagian Ketujuh — Memeriksa Instalasi Python Melalui Terminal

Kita mulai menggunakan Command Prompt agar seluruh perintah dapat diikuti dan dibaca dengan jelas melalui screen reader (NVDA / JAWS).

Langkah-Langkah Membuka Terminal:

  1. Tekan tombol Windows + R pada keyboard untuk membuka dialog Run.
  2. Ketik cmd lalu tekan Enter.
  3. Jendela Command Prompt hitam akan terbuka dan fokus siap menerima teks.

Periksa versi Python Anda dengan mengetikkan perintah berikut lalu tekan Enter:

python --version

Jika Python sudah terinstal, terminal akan menampilkan versinya, misalnya Python 3.12.5. Angka tersebut hanya contoh; versi di komputer Anda bisa berbeda asalkan 3.10 atau lebih baru.

Selanjutnya, periksa pengelola paket pip dengan perintah:

python -m pip --version

Jika kedua perintah berhasil menampilkan versi, Anda siap melanjutkan.

Troubleshooting: Jika muncul pesan "python is not recognized", coba ketik py --version. Jika py berhasil, gunakan py untuk menggantikan kata python pada langkah-langkah berikutnya. Jika tetap gagal, Anda perlu menginstal Python dari python.org dan memastikan opsi "Add python.exe to PATH" dicentang.

Bagian Kedelapan — Membuat Folder Proyek dan Lingkungan Virtual (venv)

Kita akan menyimpan seluruh proyek latihan di folder Documents komputer Anda agar rapi.

Jalankan perintah berikut satu per satu di Command Prompt:

cd %USERPROFILE%\Documents
mkdir belajar-google-adk
cd belajar-google-adk

Sekarang kita perlu membuat lingkungan Python terpisah atau virtual environment (.venv). Tujuannya agar pustaka proyek Google ADK tidak bercampur dan tidak mengganggu proyek Python lainnya di komputer.

Jalankan perintah pembuatan environment berikut:

python -m venv .venv

Tunggu beberapa saat sampai proses selesai. Jika tidak ada pesan kesalahan, aktifkan lingkungan tersebut dengan mengetik: 

.venv\Scripts\activate.bat

Setelah aktif, screen reader biasanya akan membacakan tanda (.venv) di bagian paling awal dari baris direktori terminal Anda.

Bagian Kesembilan — Menginstal Google ADK

Pastikan virtual environment masih aktif (terdapat tanda (.venv)). Pertama, perbarui pip ke versi terkini: 

python -m pip install --upgrade pip

Setelah selesai, pasang pustaka resmi Google ADK dengan mengetikkan: 

python -m pip install google-adk

Proses instalasi membutuhkan koneksi internet dan memerlukan waktu 1 hingga 3 menit. Untuk memeriksa apakah instalasi berhasil, jalankan: 

python -m pip show google-adk

Jika informasi paket google-adk (nama, versi, rangkuman pembuat) muncul di layar, berarti paket telah terpasang dengan sukses.

Bagian Kesepuluh — Membuat Gemini API Key di Google AI Studio

Google ADK membutuhkan akses ke model AI untuk memproses instruksi dan membuat keputusan pemanggilan fungsi. Kita akan menggunakan Google Gemini API.

Langkah-Langkah untuk Pengguna Screen Reader:

  1. Buka browser (Google Chrome, Microsoft Edge, atau Firefox).
  2. Akses alamat URL: https://aistudio.google.com/app/apikey
  3. Masuk (Login) menggunakan akun Google Anda.
  4. Gunakan tombol Tab atau navigasi link/button screen reader untuk mencari tombol bernama "Create API key" atau "Get API key".
  5. Ikuti petunjuk di layar hingga API key berhasil dibuat.
  6. Tekan tombol "Copy" untuk menyalin teks API key tersebut ke clipboard komputer Anda.

Penting tentang Keamanan: API key adalah informasi rahasia. Jangan membagikannya kepada orang lain, memasukkannya ke kode yang dipublikasikan di GitHub, atau mengirimkannya dalam percakapan publik.

Bagian Kesebelas — Membuat & Memahami Struktur Proyek Google ADK

Google ADK menyediakan utilitas perintah otomatis melalui terminal untuk membuat kerangka dan susunan file proyek AI Agent secara instan.

Cara 1: Membuat Struktur Proyek Secara Otomatis (Direkomendasikan)

Pastikan jendela Command Prompt Anda berada di folder induk belajar-google-adk dan Virtual Environment telah aktif (terdapat tanda (.venv)).

Ketik perintah berikut lalu tekan Enter:

adk create asisten_saya

Perintah ini akan secara otomatis membuat folder baru bernama asisten_saya beserta seluruh file kerangka yang diperlukan. Jika muncul pertanyaan pemilihan model, Anda dapat menekan Enter untuk memilih konfigurasi default.

Cara 2: Membuat Struktur Proyek Secara Manual

Jika karena alasan tertentu perintah adk create mengalami kendala, Anda dapat membuat susunan folder dan filenya secara manual dengan menjalankan perintah berikut di Command Prompt: 

mkdir asisten_saya
cd asisten_saya
type nul > agent.py
type nul > .env
type nul > __init__.py

Perintah di atas akan membuat folder asisten_saya dan tiga file kosong: agent.py, .env, dan __init__.py.

Mengenal Struktur File yang Dihasilkan

Susunan file di komputer Anda akan terlihat seperti ini:

belajar-google-adk/
│
├── .venv/                      (Folder lingkungan Python terisolasi)
│
└── asisten_saya/               (Folder proyek AI Agent)
    ├── agent.py                (File utama tempat kita menulis logika, instruksi, dan tools)
    ├── .env                    (File konfigurasi rahasia untuk menyimpan GOOGLE_API_KEY)
    └── __init__.py             (File Python penanda paket agar modul agen dapat diimpor)

Berikut adalah fungsi masing-masing file:

  • Folder asisten_saya/: Wadah direktori utama agen. Nama folder ini akan digunakan sebagai nama agent saat kita menjalankannya.
  • File agent.py: Berisi kode Python untuk mendefinisikan objek root_agent, model Gemini yang dipilih, instruksi perilaku AI, serta function tools.
  • File .env: Tempat menyimpan Gemini API Key rahasia agar aman dan tidak tercampur dalam kode program.
  • File __init__.py: File khusus Python yang berisi baris kode from . import agent agar modul agent dapat dikenali oleh Google ADK.

Bentuk Kode Dasar pada agent.py

Di dalam file agent.py, Google ADK menggunakan kelas Agent dari pustaka Google ADK dengan pola sederhana: 

from google.adk.agents import Agent

root_agent = Agent(
    name="asisten_saya",
    model="gemini-flash-latest",
    description="Asisten AI untuk membantu pengguna belajar.",
    instruction="""
    Anda adalah asisten AI yang ramah dan profesional.
    Gunakan bahasa Indonesia yang jelas dan mudah dipahami.
    Jelaskan konsep pemrograman untuk pemula secara bertahap.
    """
)

Mari kita bedah fungsi masing-masing komponen kode di atas:

Bagian Kode Fungsi & Penjelasannya
from google.adk.agents import Agent Mengimpor kelas utama untuk membangun agent dari pustaka Google ADK.
root_agent Variabel utama yang wajib dikenali oleh ADK sebagai pintu masuk (entry point) AI Agent proyek.
name Nama unik penanda agent (misal: social_media_assistant).
model Model AI yang digunakan, misalnya gemini-flash-latest yang cepat dan efisien.
description Ringkasan tujuan agent yang membantu model mengenali lingkup kemampuannya.
instruction Aturan perilaku, batasan logika, dan karakter yang wajib ditaati oleh agent (seperti SOP atau deskripsi kerja pegawai baru).
tools Daftar fungsi Python yang didaftarkan ke agent agar bisa dipanggil saat dibutuhkan.

Bagian Kedua Belas — Mengatur API Key pada File .env dengan Notepad

Kita akan menggunakan teks editor bawaan Windows yaitu Notepad agar mudah dioperasikan dengan pembaca layar (screen reader).

File .env berfungsi menyimpan variabel lingkungan yang sensitif sehingga terpisah dari kode program utama. Format konfigurasinya adalah: 

GOOGLE_API_KEY="TEMPELKAN_API_KEY_ANDA_DI_SINI"

Tips Aksesibilitas: Simpan file dengan menekan Ctrl + S. Pastikan nama filenya adalah .env dan bukan .env.txt. Jangan menghapus tanda kutip ganda yang mengapit API key Anda.

Bagian Kelima Belas — Merancang Database Sementara dan Logika Tools

Untuk tahap pembelajaran, kita menggunakan data contoh yang tersimpan di memori Python (List of Dictionaries).

Empat status alur kerja konten yang kita tetapkan secara konsisten adalah:

  • belum_dikerjakan — Rencana ide konten baru yang belum disentuh oleh tim kreatif.
  • sedang_dikerjakan — Konten yang sedang ditulis naskahnya atau dibuat desain visualnya.

  • sudah_dipublikasikan — Konten yang sudah tayang di media sosial dan memiliki metrik tayang.

Rumus Analisis Engagement Rate

Tingkat keterlibatan dihitung menggunakan rumus baku:

Engagement Rate (%) = (Total Interaksi ÷ Total Reach) × 100%

Misalnya konten ketiga di database memiliki reach 1.000 akun dan total interaksi (like + comment + share) sebesar 120, maka Engagement Rate-nya adalah: (120 / 1000) * 100% = 12%.

Bagian Keenam Belas — Menulis Kode Lengkap agent.py

from google.adk.agents import Agent

# BAGIAN 1: DATABASE KONTEN SEMENTARA (IN-MEMORY)
# =====================================================================
konten_media_sosial = [
    {
        "id": 1,
        "judul": "Edukasi aksesibilitas digital",
        "platform": "Instagram",
        "status": "sedang_dikerjakan",
        "penanggung_jawab": "Andi",
        "jadwal": "2026-10-16",
        "reach": 0,
        "interaksi": 0,
    },
    {
        "id": 2,
        "judul": "Promosi program pelatihan AI",
        "platform": "Facebook",
        "status": "menunggu_persetujuan",
        "penanggung_jawab": "Siti",
        "jadwal": "2026-10-15",
        "reach": 0,
        "interaksi": 0,

        "status": "sudah_dipublikasikan",
        "penanggung_jawab": "Rina",
        "jadwal": "2026-10-14",
        "reach": 1000,
        "interaksi": 120,
    }
]


# =====================================================================
# BAGIAN 2: FUNCTION TOOL - MONITORING KONTEN
# =====================================================================
def lihat_konten() -> list:
    """Mengembalikan daftar seluruh konten media sosial yang sedang dikelola
    beserta ID, judul, platform, penanggung jawab, jadwal, dan status progresnya."""
    return konten_media_sosial


# =====================================================================
# BAGIAN 3: FUNCTION TOOL - PENAMBAHAN KONTEN BARU
# =====================================================================
def tambah_konten(judul: str, platform: str, penanggung_jawab: str, jadwal: str) -> dict:
    """Menambahkan rencana materi konten baru ke dalam daftar kerja tim media sosial.
    Status awal secara otomatis diatur menjadi 'belum_dikerjakan'."""
    id_baru = len(konten_media_sosial) + 1
    konten_baru = {
        "id": id_baru,
        "judul": judul,
        "platform": platform,
        "status": "belum_dikerjakan",
        "penanggung_jawab": penanggung_jawab,
        "jadwal": jadwal,
        "reach": 0,
        "interaksi": 0
    }
    konten_media_sosial.append(konten_baru)
    return konten_baru


# =====================================================================
# BAGIAN 4: FUNCTION TOOL - PEMBARUAN PROGRES STATUS KONTEN
# =====================================================================
def update_status(konten_id: int, status_baru: str) -> str:
    """Memperbarui status pekerjaan konten berdasarkan ID konten.
    Pilihan status yang valid: belum_dikerjakan, sedang_dikerjakan, menunggu_persetujuan, sudah_dipublikasikan."""
    status_valid = ["belum_dikerjakan", "sedang_dikerjakan", "menunggu_persetujuan", "sudah_dipublikasikan"]
    
    status_bersih = status_baru.strip().lower()
    if status_bersih not in status_valid:
        return f"Gagal: Status '{status_baru}' tidak valid. Pilihan status yang diterima: {', '.join(status_valid)}"
    
    for item in konten_media_sosial:
        if item["id"] == konten_id:
            status_lama = item["status"]
            item["status"] = status_bersih
            return f"Sukses: Status Konten ID {konten_id} ('{item['judul']}') berhasil diubah dari '{status_lama}' menjadi '{status_bersih}'."
            
    return f"Gagal: Konten dengan ID {konten_id} tidak ditemukan di database."


# =====================================================================
# BAGIAN 5: FUNCTION TOOL - ANALISIS KINERJA & ENGAGEMENT RATE
# =====================================================================
def analisis_performa() -> list:
    """Menganalisis kinerja seluruh konten yang telah dipublikasikan dengan
    menghitung rasio keterlibatan audiens atau engagement rate (interaksi / reach * 100%)."""
    hasil = []
    for item in konten_media_sosial:
        reach = item.get("reach", 0)
        interaksi = item.get("interaksi", 0)
        
        if reach > 0:
            er = round((interaksi / reach) * 100, 2)
            hasil.append({
                "id": item["id"],
                "judul": item["judul"],
                "platform": item["platform"],
                "status": item["status"],
                "reach": reach,
                "interaksi": interaksi,
                "engagement_rate": f"{er}%",
                "keterangan": "Sudah memiliki data performa aktual"
            })
        else:
            hasil.append({
                "id": item["id"],
                "judul": item["judul"],
                "platform": item["platform"],
                "status": item["status"],
                "reach": 0,
                "interaksi": 0,
                "engagement_rate": "0%",
                "keterangan": "Belum memiliki data performa atau belum dipublikasikan"
            })
    return hasil


# =====================================================================
# BAGIAN 6: INISIALISASI AGENT UTAMA GOOGLE ADK
# =====================================================================
root_agent = Agent(
    name="social_media_assistant",
    model="gemini-flash-latest",

    5. Jika pengguna meminta analisis statistik atau perhitungan engagement rate, PANGGIL tool 'analisis_performa'.
    6. Saat memberikan saran atau rekomendasi prioritas kerja:
       - Prioritaskan konten dengan status 'menunggu_persetujuan' dan konten yang dijadwalkan segera tayang.

       - JANGAN PERNAH mengarang angka reach atau interaksi jika data belum tersedia di database.
    7. Jangan pernah menyatakan telah mengubah atau menambahkan data sebelum fungsi tool selesai dijalankan.
    """,
    tools=[lihat_konten, tambah_konten, update_status, analisis_performa]
)

Bagian Ketujuh Belas — Menjalankan AI Agent Melalui Terminal

Ingat: Dalam pola penggunaan CLI Google ADK, perintah adk run dijalankan dari direktori induk yang menaungi folder agent.

Jika Anda saat ini berada di dalam folder social_media_assistant, kembalilah satu tingkat ke atas:

cd ..

Sekarang jalankan AI Assistant Anda:

adk run social_media_assistant

Jika konfigurasi berhasil dan API key valid, terminal akan menginisialisasi sesi dan menampilkan prompt siap berbicara.

Bagian Kedelapan Belas — Menguji Fitur AI Assistant dalam 5 Skenario Nyata

Kirimkan perintah-perintah berikut satu per satu ke terminal AI Assistant untuk membuktikan bahwa Function Tools bekerja dengan baik:

Pengujian 1 — Monitoring Konten Tim

Tujuan: Menguji apakah model AI memanggil tool lihat_konten.

Tampilkan semua konten media sosial yang sedang dikelola. Kelompokkan berdasarkan status dan sebutkan penanggung jawabnya.

Pengujian 2 — Menambahkan Konten Baru

Tujuan: Menguji tool penambahan data tambah_konten.

Tambahkan konten berjudul Tips Produktivitas Digital, platform Instagram, penanggung jawab Budi, jadwal 2026-10-20.

Pengujian 3 — Memperbarui Progres Pekerjaan

Tujuan: Menguji pembaruan status konten dengan update_status.

Ubah status konten ID 1 menjadi menunggu_persetujuan.

Pengujian 4 — Analisis Performa & Engagement Rate

Tujuan: Menguji perhitungan metrik statistik dengan analisis_performa.

Analisis engagement rate seluruh konten. Jelaskan konten mana yang sudah memiliki data dan mana yang belum.

Pengujian 5 — Rekomendasi Prioritas Kerja Berbasis Data

Tujuan: Menguji penalaran strategis AI berdasarkan fakta data.

Berdasarkan data yang tersedia, apa yang harus diprioritaskan tim media sosial hari ini?

Untuk mengakhiri sesi terminal, tekan kombinasi tombol Ctrl + C.

Bagian Kesembilan Belas — Bagaimana AI Memberikan Rekomendasi Berbasis Data?

Saat Anda meminta saran prioritas kerja, AI Assistant menggunakan data nyata dari status dan jadwal untuk menyusun rekomendasi:

  • Memeriksa konten yang masih berstatus menunggu_persetujuan agar segera diperiksa oleh manajer.
  • Memastikan materi untuk jadwal terdekat sudah siap tayang tepat waktu.
  • Mengingatkan penanggung jawab konten yang masih belum_dikerjakan.
  • Meminta data performa aktual sebelum menyimpulkan efektivitas suatu kampanye.

Integritas Data vs Halusinasi: Ada perbedaan penting antara analisis berbasis data nyata dan dugaan liar AI. Jika data reach atau interaksi belum ada, AI wajib menyatakan keterbatasan tersebut secara transparan, bukan membuat angka palsu.

Bagian Kedua Puluh — Menjalankan Antarmuka Web (ADK Web)

Google ADK juga menyediakan antarmuka web untuk pengembangan visual dan inspeksi alur kerja (debugging).

Dari folder induk belajar-google-adk, jalankan perintah:

adk web --port 8000

Langkah-langkah berikutnya:

  1. Buka web browser dan kunjungi alamat: http://localhost:8000
  2. Pilih agent social_media_assistant pada antarmuka yang muncul.
  3. Temukan kotak input percakapan dan kirim pertanyaan Anda.

Catatan Aksesibilitas Pembaca Layar: Antarmuka web dapat mengalami perubahan dan belum tentu seluruh komponen grafisnya nyaman dinavigasi dengan screen reader. Untuk efisiensi dan kejelasan, mode terminal adk run sangat direkomendasikan bagi pengguna tunanetra.

Bagian Kedua Puluh Satu — Mengatasi Masalah yang Sering Muncul (Troubleshooting)

Masalah 1: "adk is not recognized"

Solusi: Virtual environment belum aktif. Jalankan perintah .venv\Scripts\activate.bat dan pastikan tulisan (.venv) muncul di awal baris terminal Anda.

Masalah 2: API key tidak ditemukan

Solusi: Periksa apakah file .env berada di dalam folder social_media_assistant, apakah namanya tepat .env (bukan .env.txt), dan baris GOOGLE_API_KEY terisi dengan benar.

Masalah 3: Model tidak tersedia atau kuota habis

Solusi: Periksa nama model pada file agent.py (misalnya gemini-flash-latest) atau gunakan akun Google AI Studio lain jika kuota penggunaan gratis telah melampaui batas harian.

Masalah 4: Gagal terhubung ke API

Solusi: Periksa kestabilan koneksi internet komputer Anda dan pastikan tidak ada firewall yang memblokir akses ke domain API Google.
