BUILDING APPLICATIONS WITH GOOGLE ANTIGRAVITY

Pertemuan ini menjadi penutup resmi dari seluruh rangkaian kurikulum AI Engineering. Jika sebelumnya kita telah mengenal konsep AI Agent secara lokal melalui Hermes Agent, kini saatnya kita memanfaatkan pendekatan agentic development untuk membangun aplikasi secara utuh menggunakan Google Antigravity. Antigravity menempatkan AI Agent sebagai rekan kerja (virtual pair programmer) yang mampu bekerja pada kode, file, terminal, pengujian, dan browser secara mandiri namun tetap berada di bawah kendali penuh manusia.

A. Tujuan Pembelajaran

Setelah mengikuti pertemuan penutup ini, peserta diharapkan mampu:

  1. Memahami konsep dasar Google Antigravity dan arsitektur agentic development.
  2. Memahami perbedaan mendasar antara AI chatbot, AI coding assistant, dan autonomous AI coding agent.
  3. Memberikan instruksi spesifikasi pembangunan aplikasi kepada AI Agent secara efektif dan terstruktur.
  4. Membuat struktur aplikasi modern menggunakan kapabilitas multi-file Antigravity.
  5. Meminta AI Agent membuat kode, melakukan refactoring, dan memperbaiki error.
  6. Menguji fungsionalitas dan integritas aplikasi yang dibangun oleh agent.
  7. Memberikan instruksi perbaikan iteratif (iterative prompt) kepada agent secara presisi.
  8. Memahami pentingnya tata kelola keamanan dan kontrol saat AI Agent menjalankan perintah sistem.
  9. Memahami konsep artifacts, tools, workspace, dan siklus tugas agent.
  10. Menerapkan prinsip aksesibilitas web bagi pengguna pembaca layar (screen reader) sejak awal perancangan.

Bagian Kesatu — Pengenalan Google Antigravity dan Era Agentic Development

Google Antigravity adalah lingkungan pengembangan perangkat lunak mutakhir yang menempatkan AI Agent bukan sekadar sebagai alat tanya-jawab, melainkan sebagai rekan kerja programmer (pair programmer virtual).

Dalam lanskap teknologi saat ini, Antigravity hadir dalam berbagai bentuk ekosistem yang terintegrasi, termasuk Antigravity 2.0, Antigravity IDE, antarmuka baris perintah CLI (Command Line Interface), serta SDK. Antigravity dirancang khusus agar AI Agent dapat beroperasi langsung pada basis kode proyek, terminal sistem, manipulasi berkas lokal, pengujian web, dan penelusuran browser secara mandiri.

Mari kita cermati pergeseran paradigma cara membuat aplikasi:

1. Editor Tradisional:
Programmer mengetik seluruh baris kode secara manual dari awal sampai selesai.

2. AI Coding Assistant Sederhana:
Programmer menulis kode, kemudian AI bertindak seperti autocomplete untuk melengkapi baris berikutnya.

3. Agentic Development (Google Antigravity):
Programmer menetapkan TUJUAN (Goal) dan SPESIFIKASI.
Agent menganalisis proyek, membuat rencana langkah kerja, mengedit banyak file sekaligus,
menjalankan terminal untuk install dependensi, menjalankan server, dan menguji aplikasi di browser.

Bayangkan kita memberikan sebuah instruksi pengembangan aplikasi: 

"Buatkan aplikasi toko online sederhana yang memiliki daftar produk, pencarian produk,
detail produk, dan tombol pemesanan langsung melalui WhatsApp."

Seorang programmer manusia biasanya akan memecah pekerjaan tersebut menjadi delapan tahapan:

  1. Membuat folder proyek dan konfigurasi awal.
  2. Menyusun struktur berkas (HTML, CSS, JavaScript, Data).
  3. Merancang tata letak antarmuka halaman.
  4. Menyusun database atau dataset produk lokal.
  5. Mengimplementasikan logika algoritma pencarian.
  6. Menyusun generator tautan pesan WhatsApp dinamis.
  7. Menjalankan server dan menguji fungsionalitas aplikasi.
  8. Mendeteksi bug dan memperbaiki kesalahan kode.

Dengan pendekatan agentic development, sebagian besar pekerjaan teknis di atas dapat didelegasikan kepada AI Agent. Namun, ada satu prinsip etika dan profesionalisme yang wajib diingat oleh setiap AI Engineer:

Prinsip Emas AI Engineering:
AI Agent membantu mempercepat pekerjaan programmer, bukan menggantikan tanggung jawab programmer. Sebagai manusia pengembang, kita tetap berkewajiban memahami logika kode yang dihasilkan, memverifikasi kualitasnya, menguji aksesibilitasnya, serta memastikan keamanannya.

Bagian Kedua — Perbedaan Chatbot, Coding Assistant, dan Coding Agent

Dalam dunia rekayasa kecerdasan buatan, ketiga istilah ini sering kali disalahartikan sebagai hal yang sama. Padahal, ketiganya memiliki kapabilitas dan batasan operasional yang sangat berbeda:

1. AI Chatbot

Chatbot hanya berfungsi dalam jendela obrolan (chat window). Ia hanya menghasilkan teks penjelasan atau jawaban percakapan. Chatbot tidak memiliki akses ke direktori kerja Anda dan tidak dapat memodifikasi file apa pun di komputer. 

Pengguna : "Apa itu Python?"
Chatbot  : "Python adalah bahasa pemrograman tingkat tinggi..."
(Selesai — tidak ada perubahan berkas atau proyek)

2. AI Coding Assistant

Coding Assistant membantu membuatkan potongan kode (code snippet) berdasarkan prompt kita. Namun, pengguna masih harus menyalin (copy) kode tersebut secara manual, membuka file di editor, lalu menempelkannya (paste) ke posisi yang tepat. 

Pengguna  : "Buat fungsi Python untuk menghitung luas persegi panjang."
Assistant : Menghasilkan potongan kode fungsi def hitung_luas(p, l): return p * l
(Programmer masih harus memasukkan kode ke berkas proyek secara mandiri)

3. Autonomous Coding Agent

Coding Agent memiliki wewenang untuk bertindak langsung di dalam repositori proyek menggunakan tools komputer. Agent dapat membaca file yang sudah ada, membuat file baru, memodifikasi beberapa berkas sekaligus, menjalankan unit test di terminal, dan memperbaiki syntax error jika terjadi kegagalan. 

Pengguna : "Buat fungsi hitung_luas, masukkan ke file kalkulator.py,
            jalankan pengujian program, dan perbaiki jika terdapat error."
Agent    : Menganalisis file -> Membuat/mengedit kalkulator.py ->
            Menjalankan 'python kalkulator.py' di terminal ->
            Memeriksa output -> Melaporkan bahwa pengujian sukses 100%.

Ringkasan Evolusi: Dari sekadar Menjawab Pertanyaan (Chatbot) $\rightarrow$ Menyarankan Potongan Kode (Assistant) $\rightarrow$ hingga Mengeksekusi Proyek Secara Mandiri (Agent).

Bagian Ketiga — Komponen Utama Arsitektur Antigravity

Di dalam ekosistem Antigravity, terdapat beberapa komponen inti yang bekerja sama secara harmonis: 

Arsitektur Antigravity:
[ Pengguna / AI Engineer ]
            │ (Memberikan Tujuan & Spesifikasi)
            v
       [ AGENT ] ◄────────┐
            │             │ (Mengevaluasi Hasil & Error)
            ├───> [ MODEL (Otak Penalaran) ]
            ├───> [ TOOLS (Terminal, File, Browser, Editor) ]
            └───> [ ARTIFACTS (Rencana, Diff Kode, Laporan) ]
            │
            v
   [ Workspace / Proyek Aplikasi ]

1. Agent

Sistem AI multi-langkah yang menerima instruksi tingkat tinggi dari pengguna, merumuskan dekomposisi rencana, memilih tools yang relevan, serta mengeksekusi tahapan kerja hingga tujuan tercapai.

2. Model

Fondasi model kecerdasan buatan (seperti keluarga model Gemini tercanggih) yang bertugas memahami bahasa alami, menganalisis struktur kode yang kompleks, dan merencanakan sintaks pemrograman yang aman.

3. Tools

Seperangkat fungsi yang diberikan kepada agent agar mampu berinteraksi dengan dunia luar:

  • File Tools: Membaca berkas proyek, membuat berkas baru, dan menyunting baris kode spesifik.
  • Terminal Tools: Menjalankan perintah shell/powershell untuk menginstal pustaka (libraries), build, atau running server.
  • Browser Tools: Membuka halaman web aplikasi secara otomatis untuk menguji tampilan, fungsionalitas tombol, dan memeriksa console error.
  • Search Tools: Menelusuri dokumentasi API terbaru di internet jika diperlukan referensi tambahan.

4. Artifacts

Dokumentasi kerja terstruktur yang dihasilkan oleh agent untuk disajikan kepada pengguna. Dokumentasi Antigravity menjelaskan bahwa artifacts dapat berupa rencana kerja (task list/plan), perbedaan perubahan kode (code diff), diagram arsitektur mermaid, hingga screenshot status aplikasi.

Nilai Plus untuk Pengguna Screen Reader: Artifacts memungkinkan programmer tunanetra memeriksa secara akurat apa saja berkas yang diubah oleh agent baris demi baris tanpa harus bingung mencari perbedaan secara visual.

Bagian Keempat — Proyek Praktik: Prototype AI Assistant Toko Online

Pada sesi pertemuan ke-10 ini, kita tidak dituntut untuk menyelesaikan seluruh sistem e-commerce raksasa dalam sekali duduk. Sebagai gantinya, kita akan membangun sebuah Prototype Fungsional Toko Online dalam durasi 60 menit yang akan menjadi pondasi kokoh untuk pengerjaan Final Project Anda.

Prototype yang kita bangun wajib memenuhi delapan spesifikasi fitur utama:

  1. Identitas Toko: Menampilkan nama toko yang representatif (contoh: "Toko Sam'an") beserta deskripsi produk.
  2. Katalog Produk: Menampilkan daftar barang dengan nama, harga, dan deskripsi singkat yang rapi.
  3. Fitur Pencarian Cepat: Pengguna dapat memfilter produk berdasarkan kata kunci secara instan.
  4. Detail Produk: Informasi lengkap mengenai spesifikasi barang yang dipilih.
  5. AI Assistant Sederhana: Fitur cerdas berbasis aturan/AI yang dapat menjawab pertanyaan seputar harga dan rekomendasi produk.
  6. Integrasi Transaksi WhatsApp: Tombol pemesanan yang otomatis memformat pesan order ke nomor WhatsApp toko.
  7. Desain Responsif: Tampilan rapi dan nyaman digunakan baik di layar ponsel maupun komputer desktop.
  8. Aksesibilitas Penuh (Screen Reader Friendly): Seluruh kontrol dapat diakses dengan keyboard dan memiliki label suara yang jelas.

1. Kopi Arabika Gayo  — Harga: Rp50.000 (Aroma harum, rasa sedikit asam segar)

Pelanggan : "Berapa harga Kopi Arabika?"

Pelanggan : "Produk apa saja yang harganya di bawah 45 ribu?"

Bagian Kelima — Teknik Merumuskan Prompt Spesifikasi untuk AI Agent

Kunci sukses utama seorang AI Engineer ketika bekerja dengan coding agent terletak pada kualitas dan kejelasan instruksi (prompting).

Hindari memberikan prompt yang terlalu singkat dan ambigu seperti: 

Prompt Buruk:
"Buatkan saya toko online." (Terlalu umum, agent akan menebak-nebak dan hasilnya sering mengecewakan)

Gunakan instruksi spesifikasi yang kaya konteks, terperinci, dan menyebutkan aturan aksesibilitas sejak awal: 

Prompt Komprehensif Siap Pakai:

Buat aplikasi web toko online sederhana satu halaman (single page web application).

Nama Aplikasi:
Toko Sam'an — Kopi & Minuman Tradisional

Tujuan:
Menampilkan katalog produk lokal dan membantu pembeli menemukan produk serta
memesan dengan cepat melalui WhatsApp.

Fitur Wajib:
1. Header toko dengan identitas yang jelas.
2. Form pencarian produk interaktif dengan filter langsung.
3. Daftar kartu produk yang menampilkan nama, harga, deskripsi, dan tombol order.
4. Kotak AI Assistant sederhana yang dapat menjawab pertanyaan seputar katalog.
5. Tombol pemesanan WhatsApp yang otomatis membuat format teks:
   "Halo Toko Sam'an, saya ingin memesan [Nama Produk] seharga [Harga]."
6. Modal atau tampilan detail produk.

Data Produk:
- Kopi Arabika Gayo, Rp50000
- Kopi Robusta Temanggung, Rp40000
- Cokelat Bubuk Organik, Rp35000

Standar Aksesibilitas Screen Reader:
1. Gunakan semantic HTML (header, main, section, footer).
2. Semua input wajib memiliki elemen label yang terhubung (label for="...").
3. Semua tombol wajib memiliki nama yang jelas (accessible name/aria-label).
4. Navigasi heading terstruktur rapi (H1 untuk judul utama, H2 untuk bagian, H3 untuk produk).
5. Seluruh fitur pencarian dan tombol harus 100% dapat dioperasikan menggunakan tombol Tab dan Enter di keyboard.
6. Hasil pencarian dan jawaban AI Assistant wajib menggunakan atribut aria-live="polite" agar dibacakan otomatis oleh NVDA/JAWS.

Teknologi:
HTML5, CSS modern (atau Bootstrap 5), dan JavaScript murni yang ringan tanpa dependensi rumit.

Setelah membuat kode:
1. Buat seluruh file yang diperlukan di folder proyek.
2. Jalankan server lokal untuk menguji aplikasi.
3. Periksa apakah ada error di console browser.
4. Buat laporan ringkas mengenai daftar berkas yang telah dibuat.

Bagian Keenam — Framework Prompt Terstruktur untuk AI Engineering

Agar hasil kerja AI Agent selalu konsisten dan berkualitas tinggi di berbagai proyek di masa depan, gunakan formulasi standar berikut: 

Framework Formula Prompt:
1. TUJUAN         : Apa tujuan utama aplikasi yang ingin dicapai?
2. FITUR          : Daftar kapabilitas fungsional yang harus ada.
3. DATA           : Data awal atau entitas yang akan diproses aplikasi.
4. TEKNOLOGI      : Bahasa pemrograman, framework, atau pustaka yang digunakan.
5. ATURAN         : Batasan desain, penamaan berkas, dan batasan sistem.
6. AKSESIBILITAS  : Kriteria navigasi keyboard, semantic markup, dan screen reader.
7. PENGUJIAN      : Prosedur verifikasi dan pengujian yang harus dijalankan.
8. HASIL AKHIR    : Format penyajian dan laporan yang diharapkan.

Tips Produktivitas: Pola prompt ini dapat Anda simpan sebagai template standar. Setiap kali Anda ingin membangun aplikasi baru bersama AI Agent, Anda cukup mengisi bagian-bagian tersebut secara sistematis.

Bagian Ketujuh — Memahami Alur Kerja Multi-Step Reasoning pada Agent

Salah satu keajaiban Antigravity adalah kemampuannya menyelesaikan pekerjaan melalui alur berpikir dan bertindak multi-langkah (multi-step reasoning loop).

Ketika Anda menekan Enter untuk mengirimkan prompt spesifikasi, perhatikan alur siklus kerja yang dilakukan agent:

INSTRUKSI PENGGUNA
       │
       v
MEMAHAMI TUJUAN (Goal Understanding)
       │
       v
MEMBUAT RENCANA KERJA (Planning & Task Decomposition)
       │
       v
MENGGUNAKAN TOOLS SISTEM FILE (Membuat index.html, style.css, app.js)
       │
       v
MENJALANKAN PROGRAM / SERVER (Terminal Execution)
       │
       v
MEMERIKSA HASIL (Inspection via Browser / Test Runner)
       │
       ├── Ada Error? ──> [ MEMPERBAIKI KODE (Self-Debugging) ] ──┐
       │                                                         │
       v (Tidak Ada Error)                                       v
HASIL AKHIR & LAPORAN ARTIFACTS ◄────────────────────────────────┘

Agent tidak hanya menghasilkan baris kode dalam satu kali tembak (one-shot). Jika saat menjalankan kode terjadi kesalahan sintaks atau port server terkunci, agent dapat membaca log error tersebut dan secara otonom memperbaikinya sebelum menyajikan hasil final kepada Anda.

Bagian Kedelapan — Seni Memberikan Instruksi Perbaikan (Iterative Prompting)

Sebagai calon AI Engineer, jangan pernah berasumsi bahwa aplikasi hasil generasi pertama akan langsung 100% sempurna tanpa cela. Kualitas perangkat lunak sejati dibentuk melalui proses iterasi yang disiplin:

Siklus Iterasi AI Engineering:
Buat (Build) ──> Uji (Test) ──> Evaluasi (Evaluate) ──> Perbaiki (Refine) ──> Uji Ulang (Re-test)

Contoh Kasus 1: Memperbaiki Aksesibilitas Tombol yang Bisu

Setelah menguji dengan NVDA, Anda menemukan bahwa tombol pencarian hanya dibacakan sebagai "Button" tanpa nama produk: 

Instruksi Perbaikan:
"Periksa seluruh elemen tombol pada file index.html dan app.js.
Screen reader membacakan tombol pencarian dan tombol pemesanan tanpa accessible name.
Tambahkan atribut aria-label yang jelas pada setiap tombol, contoh: aria-label='Pesan Kopi Arabika melalui WhatsApp'.
Pastikan seluruh ikon visual disertai teks deskriptif yang ramah screen reader.
Jalankan kembali aplikasi dan laporkan perubahannya."

Contoh Kasus 2: Menyempurnakan Logika Pencarian Produk

Instruksi Perbaikan:
"Periksa fungsi pencarian produk di app.js.
Fungsi saat ini bersifat case-sensitive sehingga kata 'kopi' huruf kecil tidak menemukan 'Kopi Arabika'.
Ubah logika pencarian menggunakan toLowerCase() agar bersifat case-insensitive, dan tambahkan aria-live='polite'
pada elemen penampung hasil agar jumlah produk yang ditemukan langsung dibacakan screen reader saat pengguna mengetik."

Bagian Kesembilan — Penerapan Prinsip Aksesibilitas Web untuk Pengguna Screen Reader

Bagi developer tunanetra, aksesibilitas bukan sekadar fitur tambahan atau pekerjaan di akhir proyek. Aksesibilitas adalah fondasi utama sebuah aplikasi berkualitas tinggi.

Tujuh pilar aksesibilitas yang wajib diperintahkan kepada AI Agent:

  1. Dukungan Keyboard Penuh: Semua interaksi (klik produk, navigasi, input pencarian, tombol order) harus dapat dijangkau dan diaktifkan hanya menggunakan tombol Tab, Shift + Tab, dan Enter / Spasi.
  2. Semantic HTML: Gunakan tag bermakna seperti <header>, <nav>, <main>, <section>, dan <footer>, bukan tumpukan tag <div> tanpa makna.
  3. Struktur Heading Teratur: Gunakan <h1> untuk nama toko, <h2> untuk nama bagian (Katalog, Pencarian, Bantuan), dan <h3> untuk nama masing-masing produk agar mudah dinavigasi dengan tombol cepat H di NVDA/JAWS.
  4. Label Input Eksplisit: Setiap kolom input pencarian wajib memiliki tag <label for="search-input">Cari Produk</label>.
  5. Accessible Names pada Tombol: Jangan membuat tombol yang hanya berisi ikon gambar tanpa teks pendamping atau tanpa aria-label.
  6. Warna Bukan Satu-Satunya Indikator: Status stok (misal: "Stok Tersedia" atau "Habis") harus dituliskan dalam teks jelas, tidak hanya ditandai dengan warna hijau atau merah.
  7. Pemberitahuan Dinamis (Live Regions): Gunakan aria-live="polite" pada kotak jawaban AI Assistant agar pembaca layar otomatis menyuarakan respons baru tanpa memindahkan fokus kursor pengguna secara kasar.

Bagian Kesepuluh — Prosedur dan Checklist Pengujian Aplikasi Secara Mandiri

Meskipun AI Agent dapat menjalankan pengujian otomatis, verifikasi langsung oleh pengguna tetap merupakan tahap akhir yang paling menentukan. Lakukan pengujian menggunakan checklist berikut:

1. Checklist Pengujian Fungsionalitas

  • [ ] Apakah aplikasi dapat dibuka di browser tanpa pesan error?
  • [ ] Apakah seluruh daftar produk muncul dengan data nama dan harga yang benar?
  • [ ] Ketika mengetikkan kata "kopi" pada kotak pencarian, apakah daftar produk tersaring secara akurat?
  • [ ] Ketika tombol pemesanan diklik, apakah browser membuka tautan WhatsApp dengan format pesan pemesanan yang rapi?
  • [ ] Apakah kotak AI Assistant memberikan jawaban yang relevan saat ditanyai harga produk?

2. Checklist Pengujian Aksesibilitas (Screen Reader & Keyboard)

  • [ ] Dapatkah Anda menavigasi seluruh halaman dari atas ke bawah hanya menggunakan tombol Tab?
  • [ ] Apakah screen reader (NVDA/JAWS) membacakan label yang jelas saat fokus berada di kotak pencarian?
  • [ ] Apakah setiap tombol memiliki accessible name yang menyebutkan tindakan dan nama produknya?
  • [ ] Dapatkah Anda berpindah antar bab menggunakan tombol cepat heading H?
  • [ ] Apakah jawaban baru dari AI Assistant otomatis terbaca oleh suara screen reader?

3. Checklist Pengujian Kode & Stabilitas

  • [ ] Apakah console browser (tekan Ctrl + Shift + I lalu pilih tab Console) bersih dari pesan error merah?
  • [ ] Jika server lokal dimatikan dan dijalankan kembali, apakah aplikasi tetap berfungsi stabil?

Bagian Kesebelas — Keamanan AI Agent: Pengendalian Akses dan Human-in-the-Loop

Karena coding agent di Antigravity memiliki kemampuan mengeksekusi perintah terminal dan memodifikasi file di komputer Anda, kepatuhan terhadap prinsip keselamatan adalah hal mutlak: 

Pedoman Keamanan Agentic:
1. Batasi Cakupan Folder : Instruksikan agent hanya memodifikasi berkas di dalam direktori kerja proyek.
2. Larang Akses Sistem  : Jangan izinkan agent menyentuh folder sistem operasi (Windows, System32, Registry).
3. Proteksi Kunci Rahasia: Jangan pernah menuliskan API Key rahasia secara terang-terangan di kode frontend terbuka.
4. Tinjau Approval Tool  : Manfaatkan fitur granular tool approval untuk menyetujui setiap perintah terminal berisiko.

Google Antigravity menerapkan prinsip Secure Defaults di mana setiap tindakan berisiko tinggi memerlukan otorisasi dari pengguna (konsep Human-in-the-Loop). Manusia tetaplah pemilik otoritas tertinggi atas sistem komputer.

Bagian Ketiga Belas — Panduan Khusus Antigravity untuk Pengguna Screen Reader

Antigravity menyediakan berbagai antarmuka interaksi, termasuk versi Command Line Interface (CLI) dan Integrated Development Environment (IDE).

Bagi pengguna tunanetra yang mengandalkan pembaca layar penuh, antarmuka berbasis CLI / Terminal sering kali memberikan kenyamanan navigasi superior karena bersifat berbasis teks murni, minim elemen visual yang membingungkan, dan dapat dikontrol penuh dengan kombinasi tombol navigasi keyboard.

Tips efisiensi saat bekerja dengan agent:

  • Gunakan Review Cursor: Di NVDA, manfaatkan tombol numpad 7, 8, 9 untuk membaca riwayat teks output agent secara teliti tanpa menggeser fokus kursor ketik.
  • Batasi Perintah Simultan: Berikan instruksi satu tujuan spesifik dalam satu giliran (turn), hindari menumpuk sepuluh tugas berbeda sekaligus agar log pekerjaan agent mudah dipahami.
  • Manfaatkan Ringkasan Artifacts: Minta agent untuk menyajikan ringkasan hasil perubahan di akhir tugas dalam bentuk daftar poin (bullet points) agar screen reader dapat membacakannya secara ringkas dan padat.

Bagian Keempat Belas — Kesimpulan: Definisi Sejati Seorang AI Engineer

Sebagai penutup pelatihan, pesan terpenting yang harus melekat dalam sanubari setiap lulusan pelatihan ini adalah:

"Seorang AI Engineer bukanlah orang yang menyerahkan seluruh pekerjaan kepada AI secara pasif."

Seorang AI Engineer sejati adalah arsitek dan nakhoda yang memahami dengan jernih:

  • Pekerjaan apa saja yang tepat dan aman untuk didelegasikan kepada AI Agent.
  • Bagaimana merumuskan instruksi spesifikasi yang presisi, kaya konteks, dan berstandar tinggi.
  • Bagaimana mengendalikan sistem keamanan dan batasan tindakan agent (Human-in-the-Loop).
  • Bagaimana memverifikasi, menguji, dan memastikan bahwa produk akhir yang dihasilkan benar, aman, inklusif, dan memberikan manfaat nyata bagi seluruh lapisan masyarakat!
